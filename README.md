# Kubernetes Notes AI Assistant

A production-style **RAG (Retrieval-Augmented Generation)** application that answers questions about Kubernetes using your own notes as the knowledge base. The system retrieves relevant sections from Markdown and text notes, then uses Azure OpenAI to generate grounded, citation-backed answers with progressive streaming.

**Live demo:** https://k8s-notes-ai.duckdns.org/

> This is a **single-VM demonstration environment** designed for learning and portfolio purposes. It is not a highly available production deployment.

---

## Features

- **Hybrid search** over Markdown and text notes using Meilisearch (text + vector).
- **Grounded answers** generated by Azure OpenAI with explicit source citations.
- **Progressive streaming** of answers via Server-Sent Events (SSE).
- **Angular frontend** with Markdown rendering and code highlighting.
- **FastAPI backend** with typed endpoints and health checks.
- **Dockerized deployment** with private internal networking.
- **Nginx reverse proxy** with HTTPS, rate limiting, and connection limits.
- **GitLab CI/CD** pipeline for automated builds and manual production deployments.
- **Terraform** configuration for Azure infrastructure (VM, networking, NSG).
- **Security controls**: private API, restricted SSH, environment separation, rate limiting.

---

## Architecture

```text
Internet
   ↓ HTTPS (443)
Nginx (Azure Ubuntu VM)
   ├── Angular production files (static)
   └── /api/* → FastAPI (private, 127.0.0.1:8000)
                ├── Meilisearch (private Docker network)
                └── Azure OpenAI (embeddings + chat)
```

- Only **Nginx** is publicly reachable (ports 80 and 443).
- **FastAPI** and **Meilisearch** are private and not exposed to the internet.
- **SSH** is restricted to a trusted IP range.
- All secrets are managed via environment files and CI/CD variables, never committed to Git.

## How It Works

### 1. Indexing notes

Markdown headings and text paragraphs are converted into searchable sections:

- Each section receives a stable ID based on file and heading.
- Text embeddings are generated using an Azure OpenAI embedding model.
- Documents and vectors are uploaded to Meilisearch.

```bash
cd k8s_Doc_OpenAI
source .venv/bin/activate
python backend/indexer.py
```

> Re-running the indexer regenerates embeddings for all sections. Avoid unnecessary re-indexing to reduce token usage.

### 2. Query flow

When a user asks a question:

1. The query embedding is generated via Azure OpenAI.
2. Meilisearch performs hybrid retrieval (text + vector).
3. Relevant sections are assembled into a grounded prompt.
4. Azure OpenAI chat model generates an answer.
5. The answer is streamed to the browser via SSE.
6. Source file and section metadata are displayed alongside the answer.

### 3. API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/health` | Health check |
| `POST` | `/search` | Hybrid search results |
| `POST` | `/answer` | Complete grounded answer with sources |
| `POST` | `/answer/stream` | SSE-streamed answer with sources |

In production, these are exposed publicly as `/api/health`, `/api/search`, `/api/answer`, and `/api/answer/stream` through Nginx.

## Local Development

### Prerequisites

- Python 3.12+
- Node.js 22+
- Docker and Docker Compose
- Git

### Environment setup

1. Create a `.env` file from `.env.example` (do not commit real secrets):

```bash
cp .env.example .env
```

2. Populate `.env` with your values:

```ini
MEILISEARCH_URL=http://localhost:7700
MEILISEARCH_KEY=your-meilisearch-master-key
AZURE_INFERENCE_ENDPOINT=https://<your-endpoint>
AZURE_FOUNDRY_API_KEY=your-api-key
AZURE_EMBEDDING_MODEL=your-embedding-deployment
AZURE_CHAT_MODEL=your-chat-deployment
```

3. Start Meilisearch:

```bash
docker compose up -d meilisearch
```

4. Install Python dependencies and run the indexer:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/indexer.py
```

5. Start the FastAPI backend:

```bash
uvicorn backend.main:app --reload --port 8000
```

6. Install and run the Angular frontend:

```bash
cd web
npm ci
ng serve
```

7. Open http://localhost:4200 in your browser.

## Production Deployment (Azure VM)

### Overview

The production environment runs on an Azure Ubuntu VM with:

- Docker and Docker Compose for application services.
- Nginx for HTTPS, static files, and API proxying.
- Let's Encrypt certificates managed by Certbot.
- Private internal Docker network for API and search.
- GitLab CI/CD for builds and manual deployments.
- Terraform for infrastructure provisioning.

### Manual deployment steps (summary)

1. Create an Azure resource group and Ubuntu VM.
2. Configure NSG rules: allow 80/443, restrict SSH.
3. Install Docker, Docker Compose, Nginx, and Certbot.
4. Clone the repository to `/opt/k8s-notes-ai`.
5. Create a production `.env` file (never commit secrets).
6. Build the Angular app: `ng build --configuration production`.
7. Copy production files to `/opt/k8s-notes-ai/frontend`.
8. Configure Nginx to serve static files and proxy `/api/*`.
9. Obtain HTTPS certificates with Certbot.
10. Run `docker compose -f infrastructure/compose.production.yaml up -d`.
11. Run the indexer on the VM.
12. Test the public URL.

All manual steps are designed to be automated via Terraform and GitLab CI/CD.

## GitLab CI/CD Pipeline

The pipeline consists of:

- **Validate**: backend tests, frontend build, Terraform validation, Compose validation.
- **Build**: build and push the FastAPI Docker image to GitLab Container Registry.
- **Plan**: generate Terraform plans for Azure VM and Foundry resources.
- **Deploy**: manual jobs to deploy the application and apply Terraform changes.

Key jobs:

- `backend_tests`: compiles and validates the Python backend.
- `frontend_build`: builds the Angular production artifacts.
- `backend_image`: builds and pushes the API Docker image.
- `deploy_production`: deploys frontend and API to the Azure VM via SSH.
- `terraform_plan_vm` / `terraform_apply_vm`: manage Azure VM infrastructure.
- `terraform_plan_foundry` / `terraform_apply_foundry`: manage Azure AI Foundry resources.

Production deployment is **manual** to prevent accidental changes.

## Security and Limitations

### What is public

- The application URL: https://k8s-notes-ai.duckdns.org/
- This README and non-sensitive source code.
- Sample Kubernetes notes (no real secrets or proprietary content).

### What is NOT public

- `.env` files (local or production).
- Azure API keys, Meilisearch keys, or any secrets.
- Terraform state files.
- SSH private keys.
- Certificate private keys.
- Internal IP addresses or infrastructure identifiers beyond what is necessary.

### Security controls

- **Network**: Only Nginx is publicly exposed; FastAPI and Meilisearch are private.
- **SSH**: Restricted to a trusted IP range; key-based authentication only.
- **Rate limiting**:
  - General API: 60 requests/minute/IP.
  - AI endpoints (`/api/answer`, `/api/answer/stream`): 5 requests/minute/IP.
  - Concurrent connection limits per IP.
- **HTTPS**: Enforced via Let's Encrypt certificates.
- **Secrets**: Managed via environment files and CI/CD variables, not committed to Git.
- **Input validation**: Maximum request sizes and timeouts configured in Nginx and FastAPI.

### Known limitations

- Single-VM architecture (no high availability or autoscaling).
- No built-in user authentication or multi-tenant isolation.
- No comprehensive observability or audit logging.
- No formal evaluation dataset or automated quality metrics.
- Re-indexing regenerates all embeddings; stale documents may persist after heading changes.

These limitations are intentional for a portfolio demo and are documented as areas for future improvement.

Potential enhancements for a production-grade system:

- **Evaluation**: golden question set, retrieval and answer-quality metrics, regression tests.
